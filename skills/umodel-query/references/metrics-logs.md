# `get_metrics` / `get_logs` — read the plan, then execute it

In the Java backend, `get_metrics` and `get_logs` return an executable query
plan. They do not fetch Prometheus or Elasticsearch data themselves unless a
real telemetry data provider is added later.

The model graph scopes the plan for you: entity ids are mapped through
`data_link.fields_mapping` and `storage_link.fields_mapping` into storage labels
or fields. Do not hand-write PromQL or Elasticsearch filters until you have read
the generated plan.

## 1. Find The Entity

```bash
curl -X POST http://localhost:8080/api/v1/query/demo/execute \
  -H 'Content-Type: application/json' \
  -d '{"query":".entity with(domain='\''devops'\'', name='\''devops.service'\'', query='\''checkout'\'') | project __entity_id__,display_name,environment"}'
```

The Java quickstart service id is:

```text
10000000000000000000000000000101
```

## 2. Discover Related Datasets

Ask the EntitySet which metric/log datasets are attached to it:

```bash
curl -X POST http://localhost:8080/api/v1/query/demo/execute \
  -H 'Content-Type: application/json' \
  -d '{"query":".entity_set with(domain='\''devops'\'', name='\''devops.service'\'') | entity-call list_data_set(['\''metric_set'\'','\''log_set'\''], true)"}'
```

In the quickstart, the relevant datasets are:

- `devops/devops.metric.service`
- `devops/devops.log.service`

## 3. Fetch A Metric Plan

Use default assistant format when you want the standard query matrix wrapper:

```bash
curl -X POST http://localhost:8080/api/v1/query/demo/execute \
  -H 'Content-Type: application/json' \
  -d "{\"query\":\".entity_set with(domain='devops', name='devops.service', ids=['10000000000000000000000000000101']) | entity-call get_metrics('devops', 'devops.metric.service', 'latency_p99_ms', step='30s')\"}"
```

In that format, the outer row has `responseType = 1`, and the plan JSON string is
in the `query` column.

Use agent format when you want the plan directly:

```bash
curl -X POST 'http://localhost:8080/api/v1/query/demo/execute?format=agent&include=spec' \
  -H 'Content-Type: application/json' \
  -d "{\"query\":\".entity_set with(domain='devops', name='devops.service', ids=['10000000000000000000000000000101']) | entity-call get_metrics('devops', 'devops.metric.service', 'latency_p99_ms', step='30s')\"}"
```

The logical plan shape is:

```jsonc
{
  "mode": "plan",
  "version": "v1.1",
  "operation": "get_metrics",
  "next_action": "execute_query",
  "source_query": "<the SPL you ran>",
  "data_source": {
    "data_set": { "ref": "devops/devops.metric.service", "kind": "metric_set" },
    "storage": { "ref": "devops/devops.prometheus.core", "type": "prometheus" },
    "data_link": { "ref": "devops/devops.service_related_to_devops.metric.service", "kind": "data_link" },
    "storage_link": { "ref": "devops/devops.metric.service_to_prometheus", "kind": "storage_link" }
  },
  "params_echo": {
    "domain": "devops",
    "name": "devops.metric.service",
    "metric": "latency_p99_ms",
    "step": "30s"
  },
  "query": {
    "dialect": "prometheus_promql",
    "endpoint": "http://localhost:9090",
    "query_type": "range",
    "step": "30s",
    "metrics": [
      {
        "name": "latency_p99_ms",
        "unit": "ms",
        "query_mode": "range",
        "generator": "histogram_quantile(...)"
      }
    ],
    "label_matchers": [
      { "label": "service_id", "operator": "=", "value": "10000000000000000000000000000101" }
    ],
    "limit": 0
  }
}
```

Dispatch on `query.dialect`. For `prometheus_promql`, read:

- `query.endpoint`: Prometheus base URL.
- `query.metrics[].generator`: PromQL template or generator expression from the
  MetricSet.
- `query.label_matchers`: storage label filters produced from model mappings.
- `query.query_type`: `range` or `instant`.
- `query.step`: range query step.

If the generator already contains the label matcher placeholder, execute it as
generated by your model pack. If the generator is a template, substitute the
label matcher values before querying Prometheus.

Example execution shape:

```bash
PROMQL='histogram_quantile(0.99, sum(rate(request_duration_bucket{service_id="10000000000000000000000000000101"}[5m])) by (le))'
curl -sG http://YOUR-PROMETHEUS:9090/api/v1/query \
  --data-urlencode "query=$PROMQL"
```

For a range query, use `/api/v1/query_range` with `start`, `end`, and `step`.

## 4. Fetch A Log Plan

```bash
curl -X POST 'http://localhost:8080/api/v1/query/demo/execute?format=agent&include=spec' \
  -H 'Content-Type: application/json' \
  -d "{\"query\":\".entity_set with(domain='devops', name='devops.service', ids=['10000000000000000000000000000101']) | entity-call get_logs('devops', 'devops.log.service', query='severity = \\\"ERROR\\\"')\"}"
```

The logical log plan shape is:

```jsonc
{
  "mode": "plan",
  "operation": "get_logs",
  "query": {
    "dialect": "elasticsearch_dsl",
    "endpoint": "http://localhost:9200",
    "index": "devops-service-logs-*",
    "filters": [
      { "label": "svc_id", "operator": "=", "value": "10000000000000000000000000000101" },
      { "label": "severity", "operator": "=", "value": "ERROR" }
    ],
    "query": "severity = \"ERROR\"",
    "limit": 0
  }
}
```

For `elasticsearch_dsl`, read:

- `query.endpoint`: Elasticsearch base URL.
- `query.index`: target index pattern.
- `query.filters`: model-generated filters to put into a bool filter.
- `query.query`: original query text for traceability.

Example execution shape:

```bash
curl -s http://YOUR-ES:9200/devops-service-logs-*/_search \
  -H 'Content-Type: application/json' \
  -d '{
    "size": 100,
    "query": {
      "bool": {
        "filter": [
          { "term": { "svc_id": "10000000000000000000000000000101" } },
          { "term": { "severity": "ERROR" } }
        ]
      }
    },
    "sort": [{ "@timestamp": { "order": "desc" } }]
  }'
```

Adjust timestamp field names to match your real index mapping.

## MCP Usage

MCP calls use the same SPL:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "workspace": "demo",
    "name": "query_spl_execute",
    "arguments": {
      "query": ".entity_set with(domain='devops', name='devops.service', ids=['10000000000000000000000000000101']) | entity-call get_metrics('devops', 'devops.metric.service', 'request_count', step='30s')",
      "format": "agent",
      "include_spec": true
    }
  }
}
```

The Java MCP response includes:

- `content[0].text`: TOON text for prompt context.
- `structuredContent.name`: tool name.
- `structuredContent.ok`: success flag.
- `structuredContent.output`: JSON query result or plan.

Prefer `structuredContent.output` for programmatic execution.

## Execution Rules

- Do not fabricate metric values from the plan. Execute the Prometheus or
  Elasticsearch query against the user's telemetry backend.
- Treat endpoints in the quickstart as local placeholders unless the environment
  actually runs Prometheus or Elasticsearch there.
- Pass auth, tenant, or TLS settings from the environment. Do not hardcode
  secrets into queries or docs.
- Keep telemetry calls read-only.
- If the user wants PaaS-style `mode='data'`, note that this Java backend
  currently returns plans; `mode=data` requires a telemetry data provider.

## Troubleshooting

- If `metric_set storage not found` or `log_set storage not found` appears, check
  `.umodel with(kind='storage_link')`.
- If matchers are missing, inspect `data_link.fields_mapping` and
  `storage_link.fields_mapping` with `?format=agent&include=spec`.
- If no rows come back from Prometheus or Elasticsearch, verify the real storage
  labels/fields match the generated matcher names (`service_id`, `svc_id`,
  `severity`, and so on).
